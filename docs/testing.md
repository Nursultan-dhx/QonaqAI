# Сценарии проверки первых двух этапов

Перед проверкой запустите приложение по README. Дата мероприятия в примерах — текущая дата плюс 30 дней; бюджет — 2 000 000 ₸, количество гостей — 80. Уведомления и сохранённые мероприятия зависят от действий, выполненных ранее.

Проверено 11 ноября 2026 года: сборка завершилась, все 12 автотестов прошли. Ниже отдельно указаны результаты ручных проверок. Команда проверки — `build.ps1`; отчёты JUnit создаются в `backend/target/surefire-reports`.

| № | Сценарий и входные данные | Ожидаемый результат | Проверка | Фактический результат |
|---|---|---|---|---|
| 1 | Открыть приложение и каталог | Демопользователь доступен без входа; каталог содержит пять площадок Астаны, фотографии и официальные источники | Автотест `bootstrapIncludesVerifiedCatalogAndDemoUser`; фотографии — вручную | Пройдено: каталог и пять фото загрузились |
| 2 | Создать «Выпускной AITU», 80 гостей, дата +30 дней, бюджет 2 млн ₸ | Мероприятие сохраняется, видно в списке; его можно открыть и изменить | Автотест `createReloadEditSelectAndDelete`; интерфейс — вручную | Пройдено: создание и редактирование через API и браузер |
| 3 | Выбрать площадку, изменить название, сохранить, затем удалить мероприятие | Выбор площадки и изменения сохраняются; после удаления запись исчезает | Автотест `createReloadEditSelectAndDelete` | Пройдено: выбор сохранён, удаление проверено автотестом |
| 4 | Переключить подбор с ECONOMY на QUALITY для 80 гостей | Порядок вариантов меняется: запас вместимости против площади на гостя; неизвестные цены остаются неизвестными | Автотест `strategiesProduceDifferentOrdersWithoutInventingPrices` | Пройдено: порядок меняется в API и браузере |
| 5 | Создать или изменить мероприятие | Observer сохраняет уведомление о действии и сообщение об обновлении подбора; их видно через API и интерфейс | Автотест `observerPersistsBothMeaningfulReactions`; интерфейс — вручную | Пройдено: оба уведомления видны в браузере |
| 6 | Сохранить мероприятие с выбранной площадкой, остановить сервер и запустить снова | Запись, выбранная площадка и уведомления доступны после перезапуска | Вручную: файловая H2; HTTP проверка после перезапуска | Пройдено: запись и выбранная площадка найдены в файловой БД после перезапуска |
| 7 | В поиске площадок ввести `RITZ`, затем запрос без совпадений | Поиск нечувствителен к регистру; для отсутствующего варианта показано понятное пустое состояние | Автотест `searchIsCaseInsensitive`; пустое состояние — вручную | Пройдено: найден Ritz, для отсутствующего запроса показан пустой список |
| 8 | Указать фильтр 400 гостей, затем 9999 гостей | В первом случае остаются только достаточно вместительные площадки; во втором список пуст | Автотест `capacityFilterExcludesSmallVenues` | Пройдено автотестом |
| 9 | Отправить пустое название или строку из пробелов | Сохранение отклонено, показано сообщение у названия | Автотест `emptyTitleIsRejected` | Пройдено автотестом |
| 10 | Указать 0 гостей | Сохранение отклонено; требуется минимум один гость | Автотест `zeroGuestsAreRejected` | Пройдено автотестом |
| 11 | Указать бюджет −1 ₸ | Сохранение отклонено; бюджет должен быть положительным | Автотест `negativeBudgetIsRejected` | Пройдено автотестом |
| 12 | Указать вчерашнюю дату | Сохранение отклонено; дата не может быть в прошлом | Автотест `pastDateIsRejected` | Пройдено автотестом |
| 13 | Выбрать площадку и отправить число гостей больше её вместимости | Сервер отклоняет действие, даже если обойти ограничения интерфейса | Автотест `oversizedSelectedVenueIsRejected` | Пройдено автотестом |
| 14 | Удалить несуществующее мероприятие; отправить неправильную дату или отрицательный фильтр гостей | API возвращает 404 или 400 с понятным сообщением, приложение не падает | Автотест `unknownEventAndMalformedInputReturnHelpfulErrors` | Пройдено автотестом |
| 15 | Добавить две-три площадки в сравнение и убрать одну | Сравниваются корректные характеристики выбранных площадок; удаление обновляет сравнение | Вручную через интерфейс | Пройдено: сравнение двух залов, выбор из таблицы и очистка |
| 16 | Проверить сайт на узком экране и пройти форму клавиатурой | Текст и действия доступны, форма не выходит за экран, фокус виден | Вручную через браузер | Пройдено: на узком экране нет горизонтального переполнения; Tab переводит фокус с названия на тип, фокус виден |

Дополнительно проверена запись после перезапуска в двух отдельных JVM: первая сохранила мероприятие с площадкой, вторая загрузила его, изменила название и сохранила новые уведомления. В изолированной среде Codex проверка доступа Java к файлу давала ложный ответ «только чтение», поэтому для этой проверки использовался временный адаптер на отдельной тестовой базе. Адаптер не входит в проект.

Граничные случаи 9–14 дополняют успешный пользовательский путь. По мере добавления пакетов, бронирования и ИИ необходимо расширять этот список, сохраняя проверки предыдущих этапов.
