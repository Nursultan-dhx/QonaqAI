# QonaqAI

Учебное веб-приложение для подготовки мероприятий в Астане. В этой версии реализуются первые два этапа: основа проекта, сохранение данных, создание мероприятия и подбор площадки. Интерфейс на русском языке; бюджет указывается в тенге.

## Запуск

Нужны JDK 21+, Maven 3.9+ и Node.js с npm. Первый запуск требует интернет для загрузки зависимостей. Скрипт автоматически ищет JDK в `JAVA_HOME`, `.tools/jdk`, пользовательской папке `.jdks` и стандартных каталогах установки; Maven — в `PATH`, `.tools` и кэше Maven Wrapper. Приоритет имеет подходящий `JAVA_HOME`.

Из папки проекта выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

Также можно открыть `start.cmd`. Скрипт собирает React и запускает Java-сервер. Откройте [http://localhost:8080](http://localhost:8080). Остановка — `Ctrl+C`. Maven-зависимости сохраняются в `.tools/m2` внутри проекта. Если порт занят, остановите приложение, которое его использует, или задайте переменную окружения `PORT` перед запуском, например `$env:PORT=8081`.

Для сборки и проверки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

Эта команда собирает интерфейс и выполняет Maven `clean package` вместе с тестами. Результат находится в `backend/target`. При ручном запуске JAR задавайте рабочую папку `backend`, чтобы использовать ту же базу.

## Что проверить

1. Создайте мероприятие: название, тип, дата, количество гостей и бюджет.
2. Найдите площадку в каталоге, откройте её описание и официальный источник.
3. Сравните варианты и переключите способ подбора.
4. Выберите площадку и сохраните мероприятие.
5. Измените параметры и проверьте обновлённый подбор и уведомления.
6. Перезапустите сервер: мероприятие должно остаться в списке.

Подробные входные данные и ожидаемые результаты приведены в [сценариях тестирования](docs/testing.md).

Демонстрационный пользователь не требует входа. Регистрация и платная подписка не входят в первые два этапа. В этой версии нет реального бронирования, оплаты или подключения ИИ.

## Архитектура

- `frontend/` — React, Vite, оформление и взаимодействие пользователя.
- `backend/` — Spring Boot, HTTP API, бизнес-логика и H2.
- `backend/src/main/resources/catalog.json` — данные площадок; каталог можно расширять.
- `backend/src/main/resources/static/images/` — локальные фотографии площадок.
- `backend/data/` — файловая база H2. База, зависимости и результаты сборки не включаются в Git.
- `docs/sources.md` — официальные источники характеристик и фотографий.
- `docs/service-examples.json` — примеры услуг для следующего этапа. Цены и логика пакетов добавляются там же, где будет реализована смета.
- `docs/testing.md` — сценарии и результаты проверки; `docs/architecture.md` — паттерны и диаграммы.

Данные пользователя сохраняются в файловой H2 после перезапуска. Не запускайте одновременно несколько экземпляров приложения с одной базой.
Если H2 сообщает, что база доступна только на чтение, запускайте `start.cmd` из обычного сеанса Windows с правами записи в `backend/data`.

## Паттерны Нурсултана

**Strategy.** Два взаимозаменяемых способа подбора площадок. `ECONOMY` сначала использует опубликованную цену, если она есть; при неизвестной цене выбирает подходящую вместимость с меньшим запасом свободных мест. Такой запас — только ориентир при подборе, он не доказывает меньшую стоимость. `QUALITY` отдаёт приоритет простору по площади на гостя. Это не рейтинг качества обслуживания.

**Observer.** Собственная система наблюдателей получает событие изменения мероприятия, обновляет рекомендации и создаёт уведомление. Это явная реализация в коде проекта, которую можно показать отдельно от механизмов Spring.

Цена «по запросу» означает, что подтверждённая публичная цена отсутствует. Приложение не придумывает расценки или доступность площадок. Вместимость нужно читать вместе с указанным форматом рассадки; окончательные условия уточняются у площадки.

## Продолжение командной работы

Нурсултан отвечает за основу, площадки, Strategy и Observer. Бейбарыс подключает пакеты, услуги и смету, реализует Factory Method и Decorator. Дастан добавляет бронирование, ИИ и предложение, реализует Facade и Builder. Все участники проверяют общий сценарий, пишут тесты и описывают собственный вклад в отчёте.

Перед передачей кода проверьте запуск на компьютере следующего участника. Общие интерфейсы и API согласовывайте до изменения контрактов. Регулярно проверяйте, что сохранённые данные и функции предыдущего этапа работают.

## Примечания для разработки

Локальные даты Git вручную установлены по просьбе автора с заданными интервалами; они не являются измерением времени выполнения разработки. Работа подготовлена с помощью ИИ. Использованные инструменты и внешние материалы нужно раскрыть в отчёте по правилам курса; каждый участник должен самостоятельно понимать, проверять и изменять свою реализацию.
